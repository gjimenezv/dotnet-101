Construir una Web API con ASP.NET Core

Objetivo: poder escribir un controller con endpoints CRUD, entender DTOs e inyección de dependencias — el core de "robust, scalable APIs" que pide el puesto.

Pensá en esto como el equivalente de un router de Express + controladores, pero con el tipado y la estructura de clases que ya viste en la lección 1.

2. Un controller de punta a punta

[ApiController]
[Route("api/[controller]")]           // "api/products"
public class ProductsController : ControllerBase
{
    private readonly IProductService _service;

    public ProductsController(IProductService service)   // ← inyección de dependencias
    {
        _service = service;
    }

    [HttpGet]
    public async Task<ActionResult<List<ProductDto>>> GetAll()
    {
        var products = await _service.GetAllAsync();
        return Ok(products);              // 200 + body
    }

    [HttpGet("{id}")]                     // "api/products/5"
    public async Task<ActionResult<ProductDto>> GetById(int id)
    {
        var product = await _service.GetByIdAsync(id);
        if (product is null) return NotFound();     // 404
        return Ok(product);
    }

    [HttpPost]
    public async Task<ActionResult<ProductDto>> Create(CreateProductDto input)
    {
        var created = await _service.CreateAsync(input);
        return CreatedAtAction(nameof(GetById), new { id = created.Id }, created);  // 201
    }
}
PiezaQué hace
[ApiController]Activa validación automática de modelo, binding inteligente — "modo API" de la clase
[Route("api/[controller]")]Define el prefijo de URL; [controller] se reemplaza por el nombre sin "Controller"
[HttpGet], [HttpPost]...Igual que router.get(), router.post() en Express, pero como atributo sobre el método
ActionResult<T>Permite retornar tanto el objeto T como códigos HTTP (NotFound(), Ok(), BadRequest())

3. DTOs: nunca expongas tu modelo de base de datos directo

Un DTO (Data Transfer Object) es un record o clase simple que define exactamente qué forma tiene el JSON que entra/sale — no el modelo completo de la base de datos. Es el mismo instinto que ya tenés en React cuando no mandás el objeto completo del backend al componente.

public record ProductDto(int Id, string Name, decimal Price);
public record CreateProductDto(string Name, decimal Price);
record con esta sintaxis ("positional record") genera automáticamente constructor, propiedades get-only e igualdad por valor. Es la forma más rápida de definir un DTO — pensalo como un type ProductDto = { id: number; name: string; price: number } de TS, pero con identidad de clase real.

4. Inyección de dependencias (DI): el contenedor hace el new por vos

En Program.cs registrás qué implementación usar para cada interfaz:

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddScoped<IProductService, ProductService>();
builder.Services.AddControllers();

var app = builder.Build();
app.MapControllers();
app.Run();

Cuando ASP.NET Core crea un ProductsController para atender un request, mira el constructor, ve que pide un IProductService, y te lo entrega automáticamente — vos nunca escribís new ProductService() a mano. Es el mismo patrón que un container de DI en Angular, o pasar dependencias explícitas por parámetro en un factory de JS, pero automatizado.

LifetimeCuándo usarlo
AddSingletonUna instancia para toda la vida de la app (ej. configuración, caché en memoria)
AddScopedUna instancia por request HTTP — el default para servicios que usan la base de datos
AddTransientInstancia nueva cada vez que se pide — para servicios livianos sin estado

5. La alternativa: Minimal API

Desde .NET 6+, existe una forma sin controllers, más parecida a Express directamente:

app.MapGet("/api/products/{id}", async (int id, IProductService service) =>
{
    var product = await service.GetByIdAsync(id);
    return product is null ? Results.NotFound() : Results.Ok(product);
});

Fuentes principales: Tutorial: Create a controller-based web API with ASP.NET Core y Tutorial: Create a Minimal API — Microsoft Learn.

Ejercicio práctico

Sin mirar arriba: escribí (en papel, notas, o un editor) un endpoint DELETE /api/products/{id} dentro de ProductsController. Debe: recibir el id, llamar a _service.DeleteAsync(id), y devolver 204 No Content si funcionó o 404 si el producto no existía.

Compará tu respuesta contra esta antes de seguir.

[HttpDelete("{id}")]
public async Task<IActionResult> Delete(int id)
{
    var deleted = await _service.DeleteAsync(id);
    if (!deleted) return NotFound();
    return NoContent();
}
