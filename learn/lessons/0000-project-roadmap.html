2. El schema — qué entidades vas a modelar

Seis entidades, pensadas para cubrir relaciones 1-a-muchos normales, una tabla puente (muchos-a-muchos vía OrderItem) y una jerarquía auto-referenciada (Employee). Es el mismo nivel de complejidad que vas a encontrar en la prueba práctica.

EntidadCamposRelaciones
CategoryId, Name1 Category → N Products
ProductId, Name, Price (decimal)N Products → 1 Category; 1 Product → N OrderItems
CustomerId, Name, City, JoinedDate1 Customer → N Orders
OrderId, OrderDate, Status (texto: Shipped/Pending/Cancelled)N Orders → 1 Customer; 1 Order → N OrderItems
OrderItemId, Quantity, UnitPrice (decimal)N OrderItems → 1 Order; N OrderItems → 1 Product
EmployeeId, Name, Title, HireDate, ManagerId (nullable, FK a sí misma)Auto-referenciada: N Employees → 1 Employee (su manager)
No hay datos de ejemplo acá a propósito — para no perder tiempo inventando filas, /home/asd/dev/ShopApi-reference-solution/seed-data.sql tiene INSERTs listos (mismo dataset que la lección 8). Corré tu migración primero, ese script después.

3. Endpoints — combinando LINQ, SQL crudo y stored procedures

De menor a mayor complejidad. La columna "Técnica" no es sugerencia libre — es a propósito para que practiques las 3 formas de tocar la base de datos que EF Core permite (lección 6, sección 5).

#EndpointTécnicaNota
1GET /productsLINQListado simple con .Include(Category)
2GET /customers/{id}LINQCon sus Orders y los Items de cada Order (.Include().ThenInclude())
3GET /customers/top-spenders?minOrders=NLINQGroupBy + filtro por cantidad de órdenes
4GET /customers/above-averageLINQGasto total sobre el promedio general. Order no tiene Total guardado — se calcula anidado desde OrderItem (ver lección 6, sección 6); el promedio se calcula como valor separado, LINQ no hace subquery correlacionada implícita
5POST /ordersLINQ (write)Crear una Order con sus OrderItems en un solo SaveChangesAsync() — practica el tracking de un grafo de entidades, no una sola tabla
6GET /customers/top-by-orders?minOrders=NStored procedureLlamá el GetTopCustomers que ya escribiste en la lección 5, desde C#, con un tipo keyless (lección 6, sección 5)
7PATCH /orders/{id}/cancelSQL crudo (write)ExecuteSqlInterpolatedAsync con un UPDATE Orders SET Status = 'Cancelled' WHERE Id = {id} — la contraparte de escritura de FromSqlRaw
8GET /employees/{id}/manager-chainSQL crudoSelf-join o CTE recursivo vía FromSqlRaw — LINQ no soporta recursión nativa
9GET /products/top-per-categorySQL crudoRANK() OVER (PARTITION BY CategoryId ORDER BY ...) vía FromSqlRaw — LINQ no tiene window functions
