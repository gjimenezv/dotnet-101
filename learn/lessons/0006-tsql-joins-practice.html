T-SQL en la práctica: JOINs complejos con varias tablas

Objetivo: escribir queries reales contra un esquema de 5 tablas — JOINs de 2, 3 y 4 tablas, LEFT JOIN, GROUP BY/HAVING y subqueries — con feedback inmediato.

Cargando motor SQL…

Este motor corre SQLite en el navegador (vía WebAssembly), no SQL Server — es la única forma de darte feedback real e inmediato sin instalar nada. La lógica de JOINs/GROUP BY/subqueries es idéntica a T-SQL, pero hay diferencias de sintaxis que NO practiques acá: T-SQL usa TOP n (SQLite usa LIMIT), GETDATE() (SQLite usa date('now')), y SQLite no tiene stored procedures. Para esas particularidades, repasá la lección 5 y el cheat sheet de T-SQL.

El esquema: mini e-commerce

Categories(Id, Name)
Products(Id, Name, CategoryId → Categories, Price)
Customers(Id, Name, City, JoinedDate)
Orders(Id, CustomerId → Customers, OrderDate, Status)
OrderItems(Id, OrderId → Orders, ProductId → Products, Quantity, UnitPrice)

Ya está cargado con datos de ejemplo: 8 clientes (2 sin ninguna orden todavía), 5 categorías, 12 productos, 13 órdenes con distintos estados (Shipped, Pending, Cancelled), y sus items.

Probá el motor

Query de calentamiento — solo apretá "Ejecutar" para ver que funciona, después modificala si querés.

Ejercicio 1 — INNER JOIN (2 tablas)

Listá el Id de orden, el nombre del cliente y la fecha, solo para órdenes con estado 'Shipped'.

SELECT o.Id, c.Name AS CustomerName, o.OrderDate
FROM Orders o
INNER JOIN Customers c ON o.CustomerId = c.Id
WHERE o.Status = 'Shipped';

Ejercicio 2 — LEFT JOIN (encontrar lo que falta)

Listá los clientes que nunca hicieron un pedido (ni siquiera uno cancelado o pendiente).

SELECT c.Id, c.Name
FROM Customers c
LEFT JOIN Orders o ON o.CustomerId = c.Id
WHERE o.Id IS NULL;

Ejercicio 3 — JOIN de 3 tablas + agregación

Para cada orden con estado 'Shipped', calculá el total (SUM(Quantity * UnitPrice)) y mostrá también el nombre del cliente. Ordená de mayor a menor total.

SELECT o.Id AS OrderId, c.Name AS CustomerName,
       SUM(oi.Quantity * oi.UnitPrice) AS OrderTotal
FROM Orders o
INNER JOIN Customers c ON c.Id = o.CustomerId
INNER JOIN OrderItems oi ON oi.OrderId = o.Id
WHERE o.Status = 'Shipped'
GROUP BY o.Id, c.Name
ORDER BY OrderTotal DESC;
¿Por qué GROUP BY o.Id, c.Name y no solo o.Id? Regla de SQL estándar: toda columna en el SELECT que no esté dentro de una función de agregación (SUM, COUNT...) debe estar en el GROUP BY. o.Id y c.Name van sueltas, SUM(...) ya está agregada. SQLite es permisivo y te deja agrupar solo por o.Id (elige cualquier valor de c.Name); SQL Server/T-SQL es estricto y tira error de compilación si falta una columna no agregada en el GROUP BY. Si te aparece ese error en la prueba, es justo esto.

Ejercicio 4 — JOIN de 4 tablas + HAVING

¿Qué categorías generaron más de $150 en ventas, contando solo órdenes 'Shipped'? Mostrá el nombre de la categoría y el total, ordenado de mayor a menor.

SELECT cat.Name AS CategoryName,
       SUM(oi.Quantity * oi.UnitPrice) AS TotalRevenue
FROM Categories cat
INNER JOIN Products p ON p.CategoryId = cat.Id
INNER JOIN OrderItems oi ON oi.ProductId = p.Id
INNER JOIN Orders o ON o.Id = oi.OrderId
WHERE o.Status = 'Shipped'
GROUP BY cat.Name
HAVING SUM(oi.Quantity * oi.UnitPrice) > 150
ORDER BY TotalRevenue DESC;

Ejercicio 5 — Subquery: por encima del promedio

¿Qué clientes gastaron (en órdenes 'Shipped') más que el promedio de gasto por cliente? Mostrá nombre y total gastado.

Pista: primero armá una subquery que calcule el total por cliente; después promediá esos totales; después comparás con HAVING.
SELECT c.Name, SUM(oi.Quantity * oi.UnitPrice) AS TotalSpent
FROM Customers c
INNER JOIN Orders o ON o.CustomerId = c.Id
INNER JOIN OrderItems oi ON oi.OrderId = o.Id
WHERE o.Status = 'Shipped'
GROUP BY c.Id, c.Name
HAVING SUM(oi.Quantity * oi.UnitPrice) > (
    SELECT AVG(CustomerTotal) FROM (
        SELECT SUM(oi2.Quantity * oi2.UnitPrice) AS CustomerTotal
        FROM Orders o2
        INNER JOIN OrderItems oi2 ON oi2.OrderId = o2.Id
        WHERE o2.Status = 'Shipped'
        GROUP BY o2.CustomerId
    )
);

Ejercicio 6 — el más difícil: COUNT(DISTINCT) a través de 4 tablas

¿Qué clientes compraron productos de más de 2 categorías distintas (en cualquier estado de orden)? Mostrá el nombre del cliente y la cantidad de categorías distintas, ordenado de mayor a menor.

SELECT c.Name, COUNT(DISTINCT p.CategoryId) AS DistinctCategories
FROM Customers c
INNER JOIN Orders o ON o.CustomerId = c.Id
INNER JOIN OrderItems oi ON oi.OrderId = o.Id
INNER JOIN Products p ON p.Id = oi.ProductId
GROUP BY c.Id, c.Name
HAVING COUNT(DISTINCT p.CategoryId) > 2
ORDER BY DistinctCategories DESC;
